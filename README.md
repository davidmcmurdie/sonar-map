# Sonar Session Map (California Recovery Divers)

**Live page: <https://davidmcmurdie.github.io/sonar-map/>**

A web page that shows DiveTeamSonarApp **sonar session files** (the `.json` files the app's
"Send a copy (.json)…" produces) on a Google satellite map: sonar legs, the full path with turns,
an optional sonar swath, marks, rejected fixes, and per-file stats.

**Your files stay in your browser.** The page reads them with the browser's `FileReader`. Nothing is
uploaded, stored, or sent to any server; this site is plain static files on GitHub Pages and has no
backend. The only network traffic is the page itself and Google Maps (map tiles and the Maps script).

## Set the Google Maps key (one-time)

Until a key is set, the page shows a "The map is not set up yet" notice instead of a map.

1. Create the key in Google Cloud (see [Google Maps API key](#google-maps-api-key) below for the
   restrictions to apply **before** you publish it).
2. Open <https://github.com/davidmcmurdie/sonar-map/edit/main/index.html> (pencil / "Edit this file" on `index.html`).
3. Near the top, find the line
   `window.SVM_GOOGLE_MAPS_API_KEY = 'YOUR_API_KEY';`
   and replace `YOUR_API_KEY` with your key, keeping the quotes:
   `window.SVM_GOOGLE_MAPS_API_KEY = 'AIza...';`
4. Click **Commit changes…** and commit directly to `main`.
5. GitHub Pages republishes in about a minute (progress under the repo's **Actions** tab). Reload
   <https://davidmcmurdie.github.io/sonar-map/>.

If you later run `node build.js`, it regenerates `index.html` with the placeholder again, so put
your key back in (or edit the key line in `build.js`'s `index` template).

## What the page does

- **Open session files…** button and drag-and-drop anywhere on the viewer; several files at once.
- Hybrid (satellite + labels) map, zoomed to fit the loaded data. **Fit all** re-fits.
- Each file gets its own colour. Per file: **Show** checkbox, **Zoom to this file**, **Remove from map**. **Clear all** removes everything.
- Sonar legs (towfish down, the file's `tracks`) as solid lines; numbered green dot at each leg start, red dot at each leg end.
- **Full path (with turns)**: the whole `breadcrumb` (every fix, including turnarounds) as a dotted line. On by default.
- **Sonar swath**: shaded band from the 5 ft blind zone out to the chosen **Range** (30 / 50 / 70 / 90 ft) on each side of every leg.
  Display only: **the file does not store the sonar range** (the app keeps it as a device setting,
  `lib/settings/sonar_range.dart`: "never written into profile/track data"), so you pick it here. Default 50 ft.
- **Rejected fixes**: fixes the app's fix gate did not draw (`rej`: `warmup`, `acc`, `jump`) are hidden, as in the app.
  Tick the box to show them as grey dots.
- **Marks** as red markers with number, time and coordinates (the file stores marks as positions plus a parallel `markTimes` list; there is no text label).
- Tap any line or marker for details of the nearest fix: time, position, accuracy, speed (mph), source, satellites, heading, rejection reason.
- Side panel per file: start date/time, duration, number of fixes, distance and fix count per leg (ft and m), total sonar
  distance, full-path distance, GPS source mix (raw GPS / Android location (fused) / fallback to fused, with the fallback reason),
  median accuracy, rejected fixes by reason, Raw GPS switch setting, number of marks.
- Older files without the per-fix fields load fine; the panel says accuracy/source were not recorded. Very old files without times show "–" for time.
- Dive Profiler (full flavour) profiles are a different format (divers, search lines, arcs) and are **not** drawn; the page says so instead of failing.
- Times are shown in the viewing device's time zone.
- Phones: the map and panel stack; one-finger panning on the map.

## Google Maps API key

Your personal key is fine at this volume. **A Maps JavaScript API key is always visible in the page
source** (the browser needs it to load the map), so it is not a secret. What protects it is the key's
restrictions in Google Cloud: with these, the key only works for the Maps JavaScript API and only on
pages served from your GitHub Pages address.

From Google's "Set up the Maps JavaScript API" (<https://developers.google.com/maps/documentation/javascript/get-api-key>, fetched October 27, 2026):
a standard key needs a Google Cloud project **with billing enabled** and the **Maps JavaScript API enabled**.

1. Google Cloud console > your project > make sure billing is linked.
2. Enable **Maps JavaScript API** (APIs & Services > Library).
3. Google Maps Platform > **Keys & Credentials** > **Create credentials > API key**.
4. **API restrictions**: Restrict key, select only **Maps JavaScript API**.
5. **Application restrictions**: **Websites**, and add `https://davidmcmurdie.github.io/*`.
   (If you also use the Squarespace snippet on a plan that allows it, add that site's addresses too,
   e.g. `https://www.YOUR-DOMAIN/*`.) Google's guidance
   (<https://developers.google.com/maps/api-security-best-practices>): "Always provide the whole referrer string, including the protocol scheme, hostname and optional port"; browsers often strip the path from the referrer, so restrict by host, not by page path.
6. Optional, to cap cost: Google Maps Platform > **Quotas** lets you lower the map-loads quota, and a billing budget alert can email you.

If the key is wrong, the API isn't enabled, or the address isn't allowed, the map area shows
"Google Maps refused the API key…".

### Free usage (verified October 27, 2026)

- Google's "Maps JavaScript API Usage and Billing" (<https://developers.google.com/maps/documentation/javascript/usage-and-billing>): "map loads trigger the Dynamic Maps SKU". This page makes one map load each time it is opened; loading files, toggling, panning and zooming are not additional loads of that SKU (my understanding of "map load", not a quoted rule).
- Google's price list (<https://developers.google.com/maps/billing-and-pricing/pricing>), Maps - loads, Essentials: **Dynamic Maps: free usage cap 10,000 per month; then $7.00 per 1,000 for 10,001–100,000** (lower rates above that).
- Pay-as-you-go page (<https://developers.google.com/maps/billing-and-pricing/pay-as-you-go>): the free usage "resets on the first day of each month, at midnight Pacific US time".
- Google's FAQ (<https://developers.google.com/maps/billing-and-pricing/faq>): since March 1, 2025 the old USD $200 monthly credit was replaced by free monthly usage per SKU (10,000 for Essentials SKUs).

So unless the page is opened more than 10,000 times in a month, Dynamic Maps usage stays within the free cap.

## Squarespace snippet (optional)

Squarespace only runs JavaScript in Code Blocks on its Core, Plus, Advanced (and some legacy) plans; on other plans it shows "Adding JavaScript and iframe embeds is a Premium Feature". That is why the site lives here on GitHub Pages; on a Basic plan, link to the Pages address from a normal Squarespace button or link instead.

If the plan allows it:


1. Open `sonar-map-viewer.html` in a text editor and replace `YOUR_API_KEY` (near the top) with your Google Maps key.
2. In Squarespace, edit the page (or create a new one, e.g. "Sonar session viewer"), click **Add block** / **+**, choose **Code**.
3. Click the pencil on the block, set **Mode** to **HTML**, make sure **Display Source** is off, paste the whole file, save.
4. Log out (or use Preview in Safe Mode) and open the page to test: Squarespace sometimes doesn't run custom code while you're logged in.
5. If it does not appear: Squarespace says code may not render if the page sits inside an **index page** or if **Ajax loading** is on; try moving it out of the index page or turning Ajax loading off.

What Squarespace says (Help Center, "Add custom code to a page with code blocks",
<https://support.squarespace.com/hc/en-us/articles/206543167-Add-custom-code-to-a-page-with-code-blocks>, last updated October 9, 2026, fetched October 27, 2026):

> "To add JavaScript or an iframe to a code block, your site needs to be on the Core, Plus, or Advanced plan."

> "Code blocks have a 400 KB limit, or about 300,000 characters." (This snippet is about 35 KB.)

> "To render CSS or JavaScript, select HTML in the Mode menu, then wrap CSS in [style] tags and JavaScript in [script] tags." (bracketed words added; the tag names didn't come through in the fetched text) (The file already has those tags.)

> "As a security measure, your code sometimes doesn't appear while you're logged in, even when visitors can view it. To view the embedded item, click Preview in Safe Mode."

The companion article "Add custom code to your site" (<https://support.squarespace.com/hc/en-us/articles/205815928-Add-custom-code-to-your-site>, seen in a search result, not fetched in full) says the Basic plan's code blocks support "plain text, HTML, Markdown, and CSS" and that "Adding JavaScript or iframes to code blocks is available in the Core, Plus, Advanced, and some legacy billing plans."
So on a Basic plan the map will not run.

The CSS is scoped to `#svm-root`, the only element id used, and all classes start with `svm-`, so the theme is untouched.

## Limitations

- Not tested against real Google Maps (no key on my side). The Google code was checked by running the real snippet in headless Chrome against a stub `google.maps` (it creates the expected lines, polygons and markers, removes them on toggle/clear, shows the "no key" message). `test/index-mock-google.js` does the same for `index.html`. The real map was only seen through the Leaflet preview, which shares the parsing, panel and drawing code.
- Uses `google.maps.Marker`, which Google has deprecated in favour of `AdvancedMarkerElement`. It still works and avoids needing a Map ID; the browser console may show a deprecation warning.
- Sonar range is not in the file, so the swath is whatever range you pick, not what was used on the water.
- Marks have no text labels in the file format, only position and time.
- Very long sessions are fine for lines; showing thousands of rejected fixes as dots may be slow on old phones.
- Session files only. Loading files from the dive team server or a shared folder by link isn't built.
